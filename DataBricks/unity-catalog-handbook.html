Unity Catalog on Databricks

A concise reference covering the Databricks platform and a complete walkthrough of Unity Catalog — governance, architecture, and data sharing.

01

What is Databricks?

Databricks is a unified, cloud-based data platform built around the Lakehouse architecture — combining the low-cost, flexible storage of a data lake with the reliability and performance of a data warehouse.

  • Runs on top of your cloud storage (AWS S3, Azure ADLS, GCS) using the open Delta Lake format.
  • Provides a single environment for data engineering, SQL analytics, machine learning, and BI.
  • Offered on AWS, Azure, and GCP, with autoscaling Spark-based compute clusters.
  • Founded by the original creators of Apache Spark, Delta Lake, and MLflow.
02

What is Unity Catalog? (At a Glance)

Unity Catalog (UC) is Databricks' unified governance layer for all data and AI assets. It provides one place to manage permissions, auditing, lineage, and discovery across every workspace in an account — instead of managing access separately per cluster or workspace.

Think of it as the central "control tower" that governs who can see and use what data, everywhere in your Databricks account.
03

Databricks Account Login — Free Edition

Databricks offers a Free Edition for learning and experimentation, with Unity Catalog enabled by default.

  1. Go to databricks.com/try-databricks and choose the Free Edition option.
  2. Sign up with an email address (or continue with Google/Microsoft SSO) and verify your email.
  3. Select or create a workspace — a Free Edition workspace is auto-provisioned with a starter Unity Catalog metastore.
  4. Log in to the workspace at your assigned URL, e.g. <workspace>.cloud.databricks.com.
  5. Explore Catalog Explorer from the left sidebar to see the default catalogs already attached.
Free Edition has usage and compute limits compared to a paid account, but it is fully sufficient to practice Unity Catalog concepts.
04

Databricks Architecture (Overview)

Databricks separates responsibilities across two planes:

Control Plane

Managed by Databricks. Hosts the web UI, job scheduler, cluster manager, and Unity Catalog's governance APIs.

Data Plane

Runs in your cloud account. Compute clusters process data that stays in your own storage.

Core layers of the platform:

  • Storage layer — cloud object storage holding Delta Lake tables.
  • Compute layer — Spark clusters, SQL warehouses, and serverless compute.
  • Governance layer — Unity Catalog, spanning every workspace in the account.
  • Workspace layer — notebooks, jobs, dashboards, and ML experiments.
05

What is Unity Catalog?

Unity Catalog is a unified governance solution for all data and AI assets across Databricks workspaces. It centralizes metadata, access control, auditing, lineage, and data discovery under one consistent model, regardless of which cloud or workspace the data lives in.

  • One metastore can be shared by multiple workspaces in a region.
  • Governs tables, views, volumes (files), ML models, functions, and dashboards — not just tables.
  • Access rules are defined once and enforced everywhere consistently.

07

Architecture & Components

Unity Catalog's architecture sits between workspaces and cloud storage:

  • Metastore — the top-level container for metadata; one per region, attached to one or more workspaces.
  • Catalog Explorer — the UI for browsing, searching, and managing governed objects.
  • Storage credentials & external locations — securely link UC to cloud storage paths without exposing raw cloud keys.
  • Access Connector / Managed Identity — the cloud-side identity UC uses to read and write storage on your behalf.
  • Unity Catalog metadata store — Databricks-managed backend recording all objects, permissions, and lineage events.
A single metastore can be attached to many workspaces, so permissions defined once apply consistently across all of them.
08

Object Hierarchy

Unity Catalog organizes data using a strict three-level namespace, plus the objects within it:

Metastore — top-level container (per region)
Catalog — groups related schemas (e.g. sales, finance)
Schema (Database) — groups related objects (e.g. raw, curated)
Tables · Views · Volumes · Functions · Models

A fully-qualified object name always follows: catalog.schema.object — e.g. sales.curated.orders.

10

Data Governance & Access Control

Unity Catalog enforces governance through standard SQL, applied consistently to every object in the hierarchy.

  • Grant/Revoke model — permissions (SELECT, MODIFY, USE CATALOG, etc.) assigned to users or groups.
  • Inheritance — privileges granted at catalog or schema level flow down to child objects.
  • Row & column-level security — row filters and column masks restrict sensitive data dynamically.
  • Attribute-based access control (ABAC) — policies driven by tags rather than object-by-object grants.
  • Audit logging — every read, write, and permission change is captured for compliance reviews.
11

Data Lineage & Discovery

  • Automatic lineage — captured at both table and column level for every read/write, with no extra configuration.
  • Lineage graph — visualizes upstream sources and downstream consumers directly in Catalog Explorer.
  • Impact analysis — quickly see what breaks downstream before changing a table.
  • Search & discovery — keyword search across catalogs, with tags, comments, and descriptions to aid findability.
  • System tables — queryable lineage and audit data for building custom governance dashboards.
12

Delta Sharing

Delta Sharing is Unity Catalog's open protocol for sharing live data across organizations and platforms — without copying or replicating it.

  • Recipients can be on Databricks or any Delta Sharing-compatible tool (Power BI, pandas, Spark, etc.).
  • Data is shared directly from your storage; the recipient always reads the latest version.
  • Shares are governed objects too — access is granted, audited, and revoked like any other UC asset.
  • Ideal for vendor/partner data exchange, monetization, and multi-cloud collaboration.
In summary: Databricks fundamentals, Unity Catalog's model, and how governed data can be securely shared beyond your own workspace all work together end-to-end.
13

Unity Catalog Secrets

Secrets are now first-class Unity Catalog securable objects, addressed with the same three-level namespace as every other asset:

catalog.schema.secret
  • Brings secrets into the UC governance model — fine-grained privileges (grant/revoke) instead of workspace-scoped secret ACLs.
  • Consistent namespace and discovery alongside tables, volumes, and models.
  • Status: Generally Available (GA)
